## ステータス

- `Draft`: 検討中。実装の根拠として使う前に未確定箇所を確認する。
- `Accepted`: 現在の合意済み仕様。実装とレビューはこの内容を基準にする。
- `Superseded`: 別文書または後続の決定に置き換えられた記録。

## 記述ルール

1. 仕様や設計判断を追加・変更するときは、対応するMarkdown文書をこのディレクトリ内で更新する。
2. 新しい文書は小文字のkebab-caseで命名し、この一覧へ追加する。
3. 確定事項と検討案を同じ表現で混在させない。未確定事項には`Draft`または「未決定」と明記する。
4. 仕様変更に対応するGitHub Issueがある場合は、文書からIssueを参照する。
5. CLIの挙動、JSON例、状態名、フィールド名は実装と同時に更新する。
6. 一時的な作業メモや生成物はこのディレクトリへ置かない。
7. 文書間で同じ仕様を重複させず、正本となる文書へリンクする。

## 更新時の確認

- 文書のステータスは適切か
- 関連文書と矛盾していないか
- READMEの文書一覧を更新したか
- 関連Issueの受け入れ条件へ反映したか
- 実装済みの場合、コードとテストも同じ仕様になっているか
